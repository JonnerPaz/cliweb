🛠️ Retos de JavaScript

No basta con leer: copia, rompe, rehaz y entiende. Cada reto te da un punto de partida — tu trabajo es transformarlo, ejecutarlo en consola y comprobar resultados.

📋 Cómo trabajar estos retos

  • Copia el código base a un archivo nuevo (ej. reto1.js) y ejecútalo con node reto1.js o pégalo en la consola del navegador (F12).
  • Lee la misión antes de tocar nada. Asegúrate de entender qué pide y qué debe devolver.
  • Intenta solo primero. Las pistas están en un desplegable — úsalas solo si te atascas.
  • Marca los criterios de la autocomprobación cuando los vayas cumpliendo.
  • Bonus track: después de resolverlo, borra el archivo y reescríbelo desde cero sin mirar. Ahí es cuando realmente lo aprendes.
1

var, let, const — elige bien

Fácil

Este código casi funciona, pero mezcla var, let y const de forma incorrecta. Algunas líneas lanzan errores; otras "funcionan" pero por las razones equivocadas (hoisting, scope de función, reasignaciones que no deberían existir).

📥 Código base — cópialo tal cual

var PI = 3.14;
PI = 3.1416;

const radio = 5;
radio = 10;

for (var i = 0; i < 3; i++) {
  setTimeout(function () { console.log("i =", i); }, 10);
}

if (true) {
  var oculto = "no tan oculto";
}
console.log(oculto);

let nombre;
nombre = "Ana";
const edad;
edad = 30;

🎯 Misión

  1. Identifica cada línea problemática y explica con un comentario // ... por qué falla o por qué es mala práctica.
  2. Corrige el código usando const por defecto y let solo cuando la variable realmente cambia.
  3. Haz que el for imprima 0, 1, 2 (no tres veces el mismo número) cambiando una sola palabra clave.
  4. Elimina cualquier var del archivo.
  5. Ejecuta el archivo y confirma que no lanza ningún error.
💡 Pistas (úsalas solo si te atascas)
  • const no permite reasignar la variable, pero sí permite mutar lo que apunta (si es objeto/array).
  • const obliga a inicializar en la declaración: const x; es error de sintaxis.
  • El clásico problema del for con var y setTimeout se resuelve con let porque crea un nuevo binding por iteración.
  • Regla práctica: empieza con const. Si el linter te obliga a reasignar, cámbialo a let. var nunca.

De function declaration a arrow function (y vuelta)

Medio

Las arrow functions son más cortas, pero no son intercambiables 1 a 1 con las funciones tradicionales: cambian el comportamiento de this y no se "hoistean". En este reto vas a convertir, romper y entender por qué.

📥 Código base

// Bloque A — convierte estas a arrow functions
function cuadrado(n) {
  return n * n;
}

function saludar(nombre) {
  return "Hola, " + nombre;
}

function sumarTodos(...nums) {
  let total = 0;
  for (const n of nums) total += n;
  return total;
}

// Bloque B — convierte estas a function declarations
const dividir  = (a, b) => a / b;
const esPar    = n => n % 2 === 0;
const aplicar  = (fn, x) => fn(x);

// Bloque C — ¿por qué este código se rompe?
const persona = {
  nombre: "Lia",
  saludar: () => {
    console.log("Soy " + this.nombre);
  }
};
persona.saludar();

console.log(despedir("Ana"));
const despedir = (n) => "Adiós, " + n;

🎯 Misión

  1. Convierte el Bloque A a arrow functions, manteniendo el mismo comportamiento.
  2. Convierte el Bloque B a function tradicionales con nombre.
  3. En el Bloque C, explica con comentarios por qué persona.saludar() imprime "Soy undefined" y arréglalo.
  4. Explica por qué despedir("Ana") lanza error antes de la declaración, mientras que una function sí se podría llamar antes.
💡 Pistas
  • Las arrow functions no tienen su propio this: heredan el del scope donde se definieron.
  • Si quieres que this apunte al objeto, usa un método con sintaxis corta: saludar() { ... } o una function tradicional.
  • Las function declarations sufren hoisting completo (definición incluida). Las arrow functions asignadas a const/let sólo el binding se hoistea, pero está en la "zona muerta temporal".

Arrays sin for: map, filter, reduce

Medio

Te entregan un catálogo de productos. Tu misión: responder cinco preguntas sin escribir ni un solo for ni while. Solo métodos de array.

Objetos anidados y desestructuración

Medio

Trabajar con datos del mundo real significa lidiar con objetos anidados (respuestas de APIs, configs, formularios). En este reto vas a extraer datos con destructuring en lugar de cadenas largas de puntos.

📥 Código base

const usuario = {
  id: 42,
  perfil: {
    nombre: "Camila",
    apellido: "Rivas",
    contacto: {
      email: "camila@ejemplo.com",
      telefono: null,
    },
  },
  direccion: {
    ciudad: "Montevideo",
    pais: "UY",
    codigoPostal: "11200",
  },
  roles: ["admin", "editor", "lector"],
  ultimasSesiones: [
    { fecha: "2026-05-01", ip: "10.0.0.1" },
    { fecha: "2026-05-05", ip: "10.0.0.2" },
    { fecha: "2026-05-10", ip: "10.0.0.3" },
  ],
};

// Usando SOLO desestructuración (nada de usuario.perfil.nombre):

// 1) Extrae nombre, apellido y email en variables sueltas
// 2) Extrae ciudad como "ciudadResidencia" (renombra)
// 3) Extrae el primer y último rol en variables: rolPrincipal, rolSecundario
// 4) Extrae la fecha de la última sesión (la del final del array)
// 5) Extrae telefono con valor por defecto "sin teléfono" si es null o undefined

// 6) Escribe una función:
//    función resumen({ perfil: { nombre }, direccion: { ciudad }, roles: [rolPrincipal] })
//    que devuelva: "Camila desde Montevideo (admin)"
function resumen(/* ... */) { /* ... */ }

console.log(resumen(usuario));

🎯 Misión

  1. Resuelve los 5 puntos usando solo desestructuración (anidada, con renombre y con defaults).
  2. Implementa la función resumen desestructurando los parámetros — sin acceder a usuario.perfil.nombre dentro del cuerpo.
  3. El default para teléfono debe activarse cuando el valor sea null o undefined. Cuidado: null + default normal de destructuring no aplica el default.
💡 Pistas
  • Renombrar: const { ciudad: ciudadResidencia } = direccion;
  • Default: const { telefono = "sin teléfono" } = contacto; — pero ojo, el default se aplica solo si la propiedad es undefined, no si es null. Puedes usar ?? "sin teléfono" después.
  • Array destructuring para tomar el último elemento: usa .at(-1) o const [, , ultima] = arr; si conoces el largo.
  • Anidada: const { perfil: { contacto: { email } } } = usuario;

Mini-programa: calcularEstadisticas(numeros)

Difícil

Vas a construir desde un archivo vacío una función que reciba un array de números y devuelva un objeto con sus estadísticas. Sin librerías, sin StackOverflow. Solo lo que aprendiste.

📐 Especificación

Implementa: calcularEstadisticas(numeros) que devuelva un objeto con:

  • min — el número más pequeño.
  • max — el número más grande.
  • promedio — media aritmética, redondeado a 2 decimales.
  • mediana — valor central (si hay par de elementos, promedio de los dos centrales).
  • moda — el valor que más se repite. Si hay empate, devuelve un array con todos los valores empatados. Si todos aparecen una sola vez, devuelve null.

🎯 Reglas no negociables

  1. Si numeros es un array vacío, devuelve null (no lances error).
  2. Si numeros no es un array o contiene elementos no numéricos, lanza un TypeError descriptivo.
  3. No mutes el array de entrada — si necesitas ordenarlo, haz una copia ([...numeros]).
  4. Usa const por defecto, arrow functions donde tenga sentido, y métodos de array siempre que puedas.
  5. Prueba tu función con al menos 4 casos:
    • [] → null
    • [5] → { min:5, max:5, promedio:5, mediana:5, moda:null }
    • [1, 2, 2, 3, 4] → moda: 2
    • [1, 1, 2, 2, 3] → moda: [1, 2]
💡 Pistas
  • Min y max: Math.min(...numeros) / Math.max(...numeros).
  • Promedio: reduce sumando, dividido por length, redondeado con Number(x.toFixed(2)).
  • Mediana: ordena una copia, mira si el length es par o impar.
  • Moda: construye un objeto { valor: conteo } con reduce, luego busca el conteo máximo y devuelve los valores que lo igualan.
  • Validación: if (!Array.isArray(numeros)) throw new TypeError(...);
