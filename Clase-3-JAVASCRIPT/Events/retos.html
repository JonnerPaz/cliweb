🛠️ Retos de Eventos

Un evento sin handler es ruido; un handler bien puesto es una conversación con el usuario. Copia, escucha, propaga, delega — y mira qué cambia.

📋 Cómo trabajar estos retos

  • Copia el código base a un archivo nuevo (ej. reto1.html) y ábrelo en el navegador con la consola abierta (F12).
  • Lee la misión antes de tocar nada. La mayoría de los bugs de eventos son por no haber leído el orden esperado.
  • Usa console.log generosamente. Los eventos son invisibles: imprime event, event.target, event.currentTarget hasta que el modelo mental encaje.
  • Marca los criterios de la autocomprobación cuando los vayas cumpliendo.
  • Bonus track: el reto 6 te pide rehacer el reto 5 desde cero. Ahí es donde realmente se asienta.
1

Tu primer addEventListener

Fácil

Hay dos formas de "escuchar" un click: la antigua (onclick="" directo en el HTML) y la moderna (addEventListener desde JS). Tu trabajo es usar la moderna y entender por qué es mejor.

📥 Código base — cópialo tal cual

<!DOCTYPE html>
<html lang="es">
<head><meta charset="UTF-8"><title>Reto 1</title></head>
<body>
  <button id="btn">Hazme click</button>
  <button onclick="alert('soy el viejo')">Botón viejo</button>

  <script>
    // TODO: agarra el botón con id="btn" y agrégale
    // un addEventListener de tipo "click" que cambie
    // su textContent a "¡Click recibido!"
  </script>
</body>
</html>

🎯 Misión

  1. Selecciona el botón con document.getElementById("btn").
  2. Usa .addEventListener("click", ...) para que al hacer click cambie su textContent a "¡Click recibido!".
  3. Agrega un segundo listener al mismo botón que también imprima en consola "clickeado". Verifica que ambos corren.
  4. En el botón con onclick="", intenta agregarle un segundo handler por el mismo método (sobreescribiendo el atributo). Observa qué pasa.
💡 Pistas (úsalas solo si te atascas)
  • La sintaxis es elemento.addEventListener("evento", funcion). El segundo parámetro es una función, no su ejecución.
  • Con addEventListener puedes agregar varios handlers al mismo evento. Con onclick="" solo uno: el último gana.
  • Para cambiar el texto: boton.textContent = "...".

2

Detectar Enter en un input

Fácil/Medio

Tienes un buscador. Quieres que al presionar Enter dentro del input se "ejecute la búsqueda" (por ahora, solo mostrar el texto en pantalla). Nada de botón de buscar.

📥 Código base

<input type="text" id="buscador" placeholder="Buscar...">
<p id="resultado"></p>

<script>
  const input = document.getElementById("buscador");
  const out   = document.getElementById("resultado");

  // TODO: escuchar el evento "keydown" en el input.
  // Si event.key === "Enter", mostrar el valor del input
  // dentro de #resultado como: "Buscando: "
</script>

🎯 Misión

  1. Agrega un listener "keydown" al input.
  2. Detecta la tecla Enter usando event.key === "Enter" (no event.keyCode — está deprecated).
  3. Cuando se presione Enter, escribe "Buscando: " + input.value dentro de #resultado.
  4. Si el input está vacío al presionar Enter, muestra "Escribe algo primero".
💡 Pistas
  • El handler recibe un parámetro: (event) => { ... }. De ahí sale event.key.
  • input.value trae siempre un string. Usa .trim() para detectar "vacío" sin espacios.
  • Imprime event completo en consola la primera vez para ver todas las propiedades disponibles.

3

Formulario sin recargar la página

Medio

El comportamiento por defecto de un formulario es recargar la página al enviar. En SPAs y formularios interactivos eso es un problema. Aprende a interceptarlo con event.preventDefault().

📥 Código base

<form id="miForm">
  <label>Nombre: <input type="text" name="nombre" required></label>
  <label>Email:  <input type="email" name="email" required></label>
  <button type="submit">Enviar</button>
</form>

<div id="salida"></div>

<script>
  const form   = document.getElementById("miForm");
  const salida = document.getElementById("salida");

  // TODO:
  // 1. Escuchar el evento "submit" del form
  // 2. Llamar a event.preventDefault() para que NO recargue
  // 3. Leer los valores y mostrarlos en #salida
</script>

🎯 Misión

  1. Agrega un listener "submit" al form.
  2. Llama a event.preventDefault() como primera línea del handler.
  3. Lee los valores usando new FormData(form) y muéstralos en #salida como una lista (<ul><li>...</li></ul>).
  4. Después de mostrar, limpia el formulario con form.reset().
💡 Pistas
  • FormData te da los pares name → value. Puedes iterarlo con for (const [k, v] of data) { ... }.
  • Si te olvidas preventDefault(), la página se recarga y parece que tu código "no hizo nada". Es el bug clásico.
  • Los inputs necesitan el atributo name para que FormData los capture.

4

Propagación: target vs currentTarget

Medio

Cuando haces click en un elemento anidado, el evento burbujea hacia arriba: dispara en el hijo, luego en el padre, luego en el abuelo. Si no entiendes esto, vas a tener bugs raros toda tu vida.

📥 Código base

<div id="abuelo" style="padding:30px;background:#fee">
  abuelo
  <div id="padre" style="padding:30px;background:#fcc">
    padre
    <div id="hijo" style="padding:30px;background:#f99">
      hijo (clickea aquí)
    </div>
  </div>
</div>

<script>
  document.getElementById("abuelo").addEventListener("click", (e) => {
    console.log("abuelo — target:", e.target.id, "| currentTarget:", e.currentTarget.id);
  });
  document.getElementById("padre").addEventListener("click", (e) => {
    console.log("padre  — target:", e.target.id, "| currentTarget:", e.currentTarget.id);
  });
  document.getElementById("hijo").addEventListener("click", (e) => {
    console.log("hijo   — target:", e.target.id, "| currentTarget:", e.currentTarget.id);
  });
</script>

🎯 Misión — 3 versiones

  1. Versión A: corre el código tal cual y haz click en "hijo". Anota el orden de los console.log. ¿Cuántas líneas aparecen? ¿Por qué?
  2. Versión B: en el handler de #hijo, agrega e.stopPropagation(). Vuelve a hacer click. ¿Qué cambió?
  3. Versión C: quita el stopPropagation. Cambia el tercer argumento de addEventListener a true en los tres (modo capture). Click en "hijo". ¿En qué orden corren ahora?
  4. Explica con tus palabras la diferencia entre e.target y e.currentTarget cuando haces click en "hijo".
💡 Pistas
  • e.target = el elemento donde realmente hiciste click. e.currentTarget = el elemento al que está pegado este listener.
  • Por default el evento viaja en fase de bubbling: hijo → padre → abuelo.
  • Con capture: true el orden se invierte: abuelo → padre → hijo.
  • stopPropagation corta el viaje en el punto donde lo llamas; los listeners siguientes en la cadena no se enteran.

✅ Autocomprobación

Delegación: un solo listener para todos

Difícil

Tienes una lista de tareas. Cada tarea tiene un botón X para eliminarla. La forma ingenua es ponerle un listener a cada botón. Eso falla cuando agregas nuevos items: los nuevos no tienen listener. La solución: delegación.

📥 Código base

<ul id="lista">
  <li>Comprar pan      <button class="del">X</button></li>
  <li>Sacar la basura  <button class="del">X</button></li>
  <li>Estudiar eventos <button class="del">X</button></li>
</ul>
<button id="addBtn">Agregar 5 items más</button>

<script>
  const lista = document.getElementById("lista");

  // ❌ Forma ingenua (NO LA USES, es para verla fallar):
  // document.querySelectorAll(".del").forEach(b =>
  //   b.addEventListener("click", () => b.parentElement.remove())
  // );

  // ✅ TODO: UN solo listener en #lista que use event.target
  // para detectar si lo clickeado fue un botón .del,
  // y en ese caso elimine su <li> padre.

  // TODO 2: cuando se haga click en #addBtn,
  // agregar 5 <li> nuevos a #lista (cada uno con su botón .del).
  // El listener delegado debe seguir funcionando con ellos
  // SIN agregarles nada extra.
</script>

🎯 Misión

  1. Agrega un único listener "click" a #lista.
  2. Dentro, revisa event.target: si es un botón con la clase del, elimina su li padre (event.target.closest("li").remove()).
  3. Implementa el botón "Agregar 5 items": cada uno debe tener su propio <button class="del">X</button>.
  4. Verifica que los nuevos items también se pueden eliminar, sin haberles agregado ningún listener individual.
  5. Compara: descomenta la "forma ingenua" y prueba que con ella los nuevos items NO se eliminan. Ahí está el "click" mental.
💡 Pistas
  • El truco está en que el listener vive en el padre, que ya existe. Cuando burbujea un click desde un hijo nuevo, el padre lo escucha.
  • event.target.matches(".del") te dice si el elemento clickeado coincide con un selector CSS.
  • element.closest("li") sube por el DOM hasta encontrar el primer li ancestro. Más robusto que parentElement.
  • Para agregar items: lista.insertAdjacentHTML("beforeend", "<li>... <button class='del'>X</button></li>").
