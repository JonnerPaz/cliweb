🧩 Retos de Componentes

Ya viste los 5 pasos de la progresión. Ahora construye tus propios componentes usando el patrón final: extends HTMLElement.

📋 Cómo trabajar estos retos

  • Todos los retos se resuelven con class MiComponente extends HTMLElement { ... } + customElements.define('mi-componente', MiComponente).
  • El componente debe poder usarse como etiqueta HTML: <mi-componente></mi-componente> en el markup.
  • Recuerda: los nombres de Custom Elements deben tener un guion (mi-modal, no mimodal).
  • Mantén CSS en archivo aparte. Mantén JS en archivo aparte. El HTML solo declara las etiquetas.
  • Cada reto incluye un esqueleto base — cópialo, complétalo, pruébalo.
1

<mi-badge> — un componente de etiqueta

Fácil

El "Hola Mundo" de los Custom Elements: una etiqueta visual estilo "Nuevo", "Beta", "Importante". Recibe un texto y un color por atributo.

📥 Esqueleto base

<!-- index.html -->
<link rel="stylesheet" href="badge.css">
<script src="badge.js" defer></script>

<mi-badge texto="Nuevo" color="verde"></mi-badge>
<mi-badge texto="Beta" color="azul"></mi-badge>
<mi-badge texto="Cuidado" color="rojo"></mi-badge>
// badge.js
class MiBadge extends HTMLElement {
  connectedCallback() {
    // TODO: leer atributos 'texto' y 'color'
    // TODO: crear un <span> con la clase "badge" y la modificadora ("badge--verde", etc.)
    // TODO: meter el texto y appendChild
  }
}
customElements.define('mi-badge', MiBadge);

🎯 Misión

  1. Implementa connectedCallback.
  2. El CSS debe definir clases .badge, .badge--verde, .badge--azul, .badge--rojo.
  3. Si no se pasa color, default a "gris".
  4. Si no se pasa texto, muestra "—".
  5. Crea 6 badges con distintos textos y colores. Todos deben verse en pantalla.
💡 Pistas
  • this.getAttribute('texto') para leer atributos.
  • Para evitar fallos: const texto = this.getAttribute('texto') || '—';
  • La regla de los nombres de Custom Element: deben tener al menos un guion.

<mi-contador> — con estado interno

Medio

Un contador con botones "+", "−" y "reset". Cada instancia mantiene su propio número independientemente.

📥 Esqueleto base

<mi-contador inicial="0"></mi-contador>
<mi-contador inicial="100" min="0" max="200"></mi-contador>
class MiContador extends HTMLElement {
  constructor() {
    super();
    this.valor = 0;
    this.min = -Infinity;
    this.max = Infinity;
  }

  connectedCallback() {
    // TODO: leer atributos 'inicial', 'min', 'max'
    // TODO: construir UI (botón -, span con valor, botón +, botón reset)
    // TODO: enganchar event listeners
    // TODO: llamar a actualizar() para pintar el estado inicial
  }

  actualizar() {
    // TODO: pintar this.valor en el span
    // TODO: deshabilitar botones si está en min o max
  }
}
customElements.define('mi-contador', MiContador);

🎯 Misión

  1. El contador empieza con el valor del atributo inicial (o 0 por defecto).
  2. "+" suma 1, "−" resta 1, "reset" vuelve al valor inicial.
  3. Respeta min y max: si llega al límite, el botón correspondiente se deshabilita.
  4. Crear 3 contadores en la misma página. Cada uno funciona independiente.
  5. Cuando el contador cambia, dispara un evento personalizado cambio con el valor en event.detail — para que el HTML que lo usa pueda escucharlo.
💡 Pistas
  • Eventos personalizados: this.dispatchEvent(new CustomEvent('cambio', { detail: { valor: this.valor } })).
  • Para escucharlo desde fuera: document.querySelector('mi-contador').addEventListener('cambio', e => console.log(e.detail.valor)).
  • Guarda referencias a los elementos internos en this en connectedCallback para no buscarlos cada vez.

<mi-toggle> — switch on/off animado

Medio

Un toggle estilo iOS: bolita que se desliza de izquierda a derecha al hacer click. Debe poder enchufarse a algo (cambiar tema, mostrar/ocultar contenido, etc.).

📥 Esqueleto base

<mi-toggle etiqueta="Modo oscuro"></mi-toggle>
<mi-toggle etiqueta="Notificaciones" activo></mi-toggle>
class MiToggle extends HTMLElement {
  connectedCallback() {
    this.activo = this.hasAttribute('activo');
    // TODO: construir la UI (label + track + thumb)
    // TODO: click en cualquier parte cambia el estado
    // TODO: dispara un evento 'toggle' con detail = { activo: bool }
  }
}
customElements.define('mi-toggle', MiToggle);

🎯 Misión

  1. El toggle muestra el atributo etiqueta a la izquierda y el switch a la derecha.
  2. Click en cualquier parte del componente (label o switch) cambia el estado.
  3. La transición de la bolita debe ser suave (no salta instantáneamente).
  4. Cuando cambia, dispara toggle con detail.activo.
  5. Bonus: conecta uno de los toggles a "cambiar tema" — al activarse, document.body recibe la clase .dark que define un esquema de colores oscuros.
💡 Pistas
  • Toda la animación va en CSS con transition. JS solo agrega/quita una clase .activo.
  • El thumb (la bolita) se mueve con transform: translateX(...) cuando el track tiene la clase activa.
  • Para accesibilidad: agrega role="switch" y aria-checked.

<mi-modal> — diálogo abrible

Difícil

Un modal reutilizable. Lo metes en el HTML cerrado por defecto, y desde fuera lo abres llamando a document.querySelector('mi-modal').abrir(). Click en el fondo o en "✕" lo cierra. Esc también lo cierra.

📥 Esqueleto base

<button id="abrir">Abrir modal</button>

<mi-modal titulo="¿Estás seguro?">
  <p>Esta acción no se puede deshacer.</p>
  <p>¿Quieres continuar?</p>
</mi-modal>

<script>
  document.getElementById('abrir').addEventListener('click', () => {
    document.querySelector('mi-modal').abrir();
  });
</script>
class MiModal extends HTMLElement {
  connectedCallback() {
    // PISTA: guarda el contenido interno antes de construir el modal alrededor
    const contenido = this.innerHTML;
    this.innerHTML = '';

    // TODO: construir backdrop + diálogo + cabecera con título + botón cerrar
    // TODO: meter `contenido` dentro del cuerpo del diálogo
    // TODO: que arranque oculto
    // TODO: cerrar con: botón ✕, click en backdrop, tecla Escape
  }

  abrir() { /* TODO */ }
  cerrar() { /* TODO */ }
}
customElements.define('mi-modal', MiModal);

🎯 Misión

  1. El modal aparece centrado con fondo oscurecido (backdrop).
  2. El contenido HTML que pones entre <mi-modal>...</mi-modal> debe aparecer dentro del modal cuando se abre.
  3. Cerrar de 3 formas: botón "✕", click en el backdrop (pero NO en el diálogo), tecla Escape.
  4. Cuando se abre, el foco salta al botón de cerrar (accesibilidad).
  5. Dispara eventos abierto y cerrado en cada acción.
💡 Pistas
  • Para Escape: document.addEventListener('keydown', e => { if (e.key === 'Escape') this.cerrar(); }). Recuerda removerlo cuando se cierra.
  • Click en backdrop pero no en diálogo: chequear e.target === backdrop.
  • Mostrar/ocultar: agregar/quitar una clase .abierto con CSS display: none vs display: flex.

<mi-card> — tarjeta de producto componible

Difícil

El reto final integra TODO: atributos, slots (contenido interno), estado, eventos. Vas a construir una tarjeta de producto con favorito.

📥 Esqueleto base

<mi-card imagen="https://picsum.photos/300/200" precio="29.99">
  <h3 slot="titulo">Mi producto</h3>
  <p slot="descripcion">Descripción del producto que vendes.</p>
</mi-card>

🎯 Misión

  1. La card muestra: imagen arriba (del atributo), título y descripción (vienen del contenido interno por slot), precio (atributo), botón "❤️ favorito".
  2. El botón favorito alterna entre 🤍 y ❤️ al hacer click (estado interno).
  3. Al cambiar el favorito, dispara un evento favorito-cambiado con { favorito: bool }.
  4. Crea al menos 4 cards en la misma página con productos distintos.
  5. Conecta un listener global que cuente cuántos favoritos hay y muestre el total en pantalla.
💡 Pistas
  • Slots sin Shadow DOM: sin Shadow DOM no tienes <slot> real, pero puedes leer el contenido con this.querySelector('[slot="titulo"]') antes de reorganizarlo, o simplemente reordenar el DOM en connectedCallback.
  • Para el contador global: document.querySelectorAll('mi-card').forEach(c => c.addEventListener('favorito-cambiado', actualizar)).
  • Encapsula los métodos: this.toggleFavorito() es más legible que un montón de listeners inline.

✅ Autocomprobación

★

Bonus — Composición

Difícil

Combina tres de tus componentes en una sola página. Por ejemplo:

  • Una lista de <mi-card> con productos.
  • Cada card tiene un <mi-badge> dentro indicando "Nuevo" / "Oferta" / "Agotado".
  • Un <mi-toggle> arriba que filtra "solo favoritos".

Esto es exactamente cómo se construyen aplicaciones reales: componentes pequeños que se anidan y se comunican. Lo que acabas de hacer es, conceptualmente, lo que React/Vue/Angular hacen — pero con la API nativa del navegador.
