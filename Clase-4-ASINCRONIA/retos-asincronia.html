⏳ Retos de Asincronía

La asincronía no se entiende leyendo. Copia, ejecuta, predice qué pasa, observa lo que pasó de verdad.

📋 Cómo trabajar estos retos

  • Cada reto te entrega código que simula operaciones asíncronas con setTimeout — no necesitas conexión a internet.
  • Antes de ejecutar: predice en qué orden saldrán los console.log. Anótalo.
  • Ejecuta. Compara tu predicción con la realidad. Si fallaste, ahí es donde está el aprendizaje.
  • Bonus: vuelve a escribir el reto sin mirar. Si te sale al primer intento, lo entendiste.
1

Callback Hell: el problema antes de la solución

Fácil

Para entender por qué existen las promesas, primero hay que sufrir su ausencia. Este reto te hace escribir código asíncrono al estilo viejo (callbacks anidados) para que veas con tus ojos el problema.

📥 Código base

// Simulan operaciones lentas: cada una tarda 1 segundo y luego llama al callback
function obtenerUsuario(id, callback) {
  setTimeout(() => {
    console.log('1. Usuario obtenido');
    callback({ id, nombre: 'Ana' });
  }, 1000);
}

function obtenerPosts(usuario, callback) {
  setTimeout(() => {
    console.log('2. Posts obtenidos');
    callback([{ id: 1, titulo: 'Hola' }, { id: 2, titulo: 'Adiós' }]);
  }, 1000);
}

function obtenerComentarios(post, callback) {
  setTimeout(() => {
    console.log('3. Comentarios obtenidos');
    callback(['¡genial!', 'muy bueno']);
  }, 1000);
}

// TU CÓDIGO AQUÍ: encadena las 3 funciones usando callbacks anidados.
// Al final, imprime los comentarios del primer post del usuario 42.

🎯 Misión

  1. Llama a obtenerUsuario(42, ...).
  2. Cuando llegue, llama a obtenerPosts(...) con ese usuario.
  3. Cuando lleguen los posts, llama a obtenerComentarios(...) con el primero.
  4. Al final, imprime los comentarios.
  5. Cuenta cuántos niveles de indentación tiene tu solución. Anota la cifra. La vas a comparar con el reto 4.
💡 Pistas
  • La forma "natural" es anidar funciones de flecha: obtenerUsuario(42, (u) => { obtenerPosts(u, (p) => { ... }) }).
  • Si tu IDE empieza a quejarse del ancho de pantalla, estás en la "pirámide de la perdición". Ese es el punto del reto.

all vs race vs allSettled

Medio

Tres operaciones independientes corren en paralelo. La pregunta es: ¿cuándo y cómo quieres que te avisen del resultado? Cada combinador responde a una necesidad distinta.

📥 Código base

function tarea(nombre, ms, debeFallar = false) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (debeFallar) reject(`${nombre} falló`);
      else resolve(`${nombre} OK`);
    }, ms);
  });
}

const t1 = tarea('A', 1000);
const t2 = tarea('B', 500, true);   // ¡esta falla!
const t3 = tarea('C', 800);

// TU CÓDIGO: ejecuta las 3 versiones y observa la diferencia.

🎯 Misión

  1. Predice antes de ejecutar: ¿qué imprime cada uno?
    • Promise.all([t1, t2, t3])
    • Promise.race([t1, t2, t3])
    • Promise.allSettled([t1, t2, t3])
  2. Ejecuta los 3 y compara con tu predicción.
  3. Cambia debeFallar a false en t2 y vuelve a predecir + ejecutar.
  4. Responde por escrito: ¿cuándo usarías cada uno en un proyecto real?
💡 Pistas
  • Promise.all falla TODO si UNA falla. Pero te da las respuestas en el mismo orden que las pasaste.
  • Promise.race resuelve (o rechaza) con la PRIMERA que termine, ganen o pierdan.
  • Promise.allSettled nunca rechaza: te entrega un array de {status: 'fulfilled', value} o {status: 'rejected', reason}.

Refactor: el mismo flujo en 3 estilos

Medio

Toma el flujo del reto 1 (callback hell). Tu misión: el mismo resultado, en tres versiones.

📥 Punto de partida

// Mismas 3 funciones del reto 1, pero ahora retornan promesas:
function obtenerUsuario(id) {
  return new Promise(r => setTimeout(() => r({ id, nombre: 'Ana' }), 1000));
}
function obtenerPosts(usuario) {
  return new Promise(r => setTimeout(() => r([{ id: 1, titulo: 'Hola' }]), 1000));
}
function obtenerComentarios(post) {
  return new Promise(r => setTimeout(() => r(['¡genial!']), 1000));
}

🎯 Misión — escribe TRES versiones

  1. Versión A — Promesas con .then(): encadena las 3 con .then() y un .catch() final.
  2. Versión B — Async/await: crea una función async function flujo() con tres await y un try/catch.
  3. Versión C — Optimizada: imagina que obtenerComentarios NO depende de obtenerPosts (que ambas dependen solo del usuario). ¿Cómo lo paralelizarías con Promise.all?
  4. Compara visualmente las 3. ¿Cuál es más legible? ¿Cuál es más rápida?
💡 Pistas
  • Versión A: cada .then() debe retornar la siguiente promesa para que se encadene.
  • Versión B: const usuario = await obtenerUsuario(42); const posts = await obtenerPosts(usuario); ...
  • Versión C: const [posts, comentarios] = await Promise.all([obtenerPosts(usuario), obtenerComentarios(usuario)]);

Checkout con timeout global

Difícil

Vas a simular un sistema de checkout de e-commerce: 3 pasos encadenados, manejo de errores en niveles correctos, y un timeout global. Si todo el proceso tarda más de 5 segundos, abortar.

📥 Código base

// Cada paso retorna una promesa que puede resolver o fallar.
function validarStock(productos) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (productos.length === 0) reject(new Error('Carrito vacío'));
      else resolve(productos);
    }, 1500);
  });
}

function cobrar(usuario, total) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (total > 1000) reject(new Error('Tarjeta rechazada'));
      else resolve({ idTransaccion: Math.random().toString(36).slice(2) });
    }, 2000);
  });
}

function enviarConfirmacion(email, idTransaccion) {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve(`Email enviado a ${email} con tx ${idTransaccion}`);
    }, 1000);
  });
}

// TU CÓDIGO AQUÍ: implementa checkout(usuario, productos, total)
// que orqueste los 3 pasos con timeout global de 5 segundos.

🎯 Misión

  1. Escribe async function checkout(usuario, productos, total) que llame a los 3 pasos en orden.
  2. Usa try/catch para capturar errores y decidir qué hacer en cada caso:
    • Si validarStock falla: log "Carrito inválido".
    • Si cobrar falla: log "Pago rechazado, intenta otra tarjeta".
    • Si enviarConfirmacion falla: log "Pago OK pero email no se envió" (el pago YA pasó, no debe fallar todo).
  3. Agrega un timeout global de 5s: si el proceso entero no termina en 5s, abortar con error. Usa Promise.race entre tu flujo y un timeout.
  4. Prueba los 4 escenarios: éxito, carrito vacío, total > 1000, y un "lento" (modifica los tiempos para que sumen >5s).
💡 Pistas
  • Timeout helper: const timeout = (ms) => new Promise((_, r) => setTimeout(() => r(new Error('Timeout')), ms));
  • Para combinar: const resultado = await Promise.race([miFlujo(), timeout(5000)]);
  • El try/catch de enviarConfirmacion debería estar ANIDADO dentro del éxito de cobrar — no abortar la transacción si solo falla el email.
