🌐 Retos de Fetch

Consumir APIs es el 80% del trabajo de un dev frontend moderno. Cada reto te pone frente a una API real.

📋 Cómo trabajar estos retos

  • Todos los retos usan APIs públicas y gratuitas: JSONPlaceholder, PokeAPI, etc. Solo necesitas conexión.
  • Prueba primero las URLs en el navegador (paste y enter) — verás el JSON tal cual.
  • Abre la consola del navegador (F12) y la pestaña Network: ahí ves todos los requests, sus headers y respuestas.
  • NO uses librerías (axios, jQuery). Solo fetch nativo.
1

GET básico — tu primer fetch

Fácil

Lo más simple que puedes hacer con fetch: pedir datos y mostrarlos. Aquí construyes el "Hello World" del consumo de APIs.

📥 HTML base

<!DOCTYPE html>
<html>
<body>
  <h1>Usuarios</h1>
  <ul id="lista"></ul>

  <script>
    // TU CÓDIGO AQUÍ
  </script>
</body>
</html>

🎯 Misión

  1. Usa fetch('https://jsonplaceholder.typicode.com/users') para obtener usuarios.
  2. Parsea la respuesta a JSON.
  3. Por cada usuario, agrega un <li> a la lista con ${nombre} — ${email}.
  4. Hazlo dos veces: una con .then() y otra con async/await. Compara legibilidad.
💡 Pistas
  • Versión async: const res = await fetch(url); const data = await res.json(); data.forEach(...).
  • Para agregar al DOM sin innerHTML: document.createElement('li') y appendChild.
  • El res.json() también es asíncrono — devuelve una promesa.

El error más común con fetch

Medio

Spoiler: fetch NO falla con 404. Es el error #1 que ven los devs juniors. Aquí lo aprendes una vez y nunca más lo olvidas.

📥 Código base

// Implementa esta función "segura" para envolver fetch:
async function fetchSeguro(url) {
  // TU CÓDIGO AQUÍ
  // Debe:
  // 1. Manejar errores de red (catch).
  // 2. Verificar response.ok y lanzar error con el status HTTP si no es 2xx.
  // 3. Parsear JSON con manejo de error.
  // 4. Retornar siempre { data, error } — nunca lanzar.
}

// Pruébala con 3 URLs:
fetchSeguro('https://jsonplaceholder.typicode.com/users/1');      // ✅ existe
fetchSeguro('https://jsonplaceholder.typicode.com/users/9999');   // 404
fetchSeguro('https://esto-no-existe-real.xyz/api');               // red falla

🎯 Misión

  1. Implementa fetchSeguro. Pista en el código.
  2. Antes de ejecutarla: predice qué retorna cada caso (data llena vs error con mensaje específico).
  3. Ejecuta los 3 y verifica.
  4. Responde: ¿por qué fetch trata un 404 como "éxito" (response.ok = false)?
💡 Pistas
  • Estructura: try { const res = await fetch(url); if (!res.ok) throw new Error(`HTTP ${res.status}`); const data = await res.json(); return { data, error: null }; } catch (err) { return { data: null, error: err.message }; }
  • El catch atrapa errores de red (DNS, sin internet) Y los errors que tú mismo lanzas con throw.

POST con body JSON

Medio

Hasta ahora solo leíste. Ahora vas a "enviar" datos. JSONPlaceholder es un servidor de pruebas que pretende guardar pero no guarda — perfecto para aprender.

📥 Código base

// Envía un nuevo "post" a JSONPlaceholder.
// El body debe ser un objeto con: title, body, userId.

async function crearPost(post) {
  // TU CÓDIGO AQUÍ
}

crearPost({
  title: 'Mi primer POST',
  body: 'Estoy aprendiendo fetch',
  userId: 1
}).then(console.log);

🎯 Misión

  1. Implementa crearPost con fetch:
    • URL: https://jsonplaceholder.typicode.com/posts
    • Método: POST
    • Header: Content-Type: application/json
    • Body: el objeto convertido a JSON con JSON.stringify
  2. Espera la respuesta y parsea JSON. Verás que retorna lo que enviaste + un id.
  3. Bonus: abre Network en DevTools, ejecuta el POST y observa: método, headers, body, response. Esto es lo que vas a depurar el resto de tu carrera.
💡 Pistas
  • Segundo argumento de fetch: { method: 'POST', headers: {...}, body: JSON.stringify(post) }.
  • Si olvidas JSON.stringify, el servidor recibe [object Object] y no funciona.
  • JSONPlaceholder asigna id=101 (no incrementa real, es solo para pruebas).

Paralelo vs secuencial — mídelo

Medio

"Espera el primero, luego el segundo, luego el tercero" es la forma más obvia. Pero si las 3 peticiones son independientes, es tres veces más lenta de lo necesario. Aquí lo demuestras con un benchmark.

📥 Código base

// Vas a obtener: 1 usuario, sus 10 posts y todos los comentarios del primer post.
// Endpoints:
//   GET /users/1
//   GET /posts?userId=1
//   GET /comments?postId=1
// (todos en https://jsonplaceholder.typicode.com)

async function versionSecuencial() {
  const t = performance.now();
  // TU CÓDIGO: 3 awaits separados, uno después del otro.
  console.log('Secuencial:', performance.now() - t, 'ms');
}

async function versionParalela() {
  const t = performance.now();
  // TU CÓDIGO: 3 fetches en paralelo con Promise.all.
  console.log('Paralelo:', performance.now() - t, 'ms');
}

🎯 Misión

  1. Implementa versionSecuencial(): 3 await uno tras otro.
  2. Implementa versionParalela() con Promise.all.
  3. Ejecuta cada una 3 veces y anota los tiempos.
  4. Pregunta clave: si las 3 peticiones independientemente tardan ~300ms, ¿por qué la secuencial tarda ~900ms y la paralela ~300ms?
  5. Reto extra: ¿cuándo NO debes paralelizar? (pista: si el resultado de A determina la URL de B).
💡 Pistas
  • Paralelo: const [user, posts, comments] = await Promise.all([fetch(...).then(r=>r.json()), ...]);
  • El paralelismo solo funciona si las peticiones son independientes entre sí.

Mini-app: buscador de Pokémon (PokeAPI)

Difícil

Construye una mini-app real: input + botón, escribir un nombre de Pokémon → mostrar su info. Maneja loading, errores, "no encontrado" y cache simple.

📦 Punto de partida con UI ya lista: ejercicio-pokeapi.html contiene una Pokeball animada que puedes usar como contenedor visual. Aprovéchala — el ejercicio guiado tiene instrucciones completas allí.

🎯 Misión (resumen)

  1. Input para nombre del Pokémon + botón "Buscar".
  2. URL: https://pokeapi.co/api/v2/pokemon/{nombre} (acepta nombre o id).
  3. Mostrar: nombre, sprite (imagen), altura, peso, tipos.
  4. Estados claros: loading, éxito, "no encontrado" (404), error de red.
  5. Cache: si ya buscaste "pikachu", no vuelvas a hacer fetch — lee del cache.

Especificación detallada + criterios de evaluación: abre el ejercicio PokeAPI.

💡 Pistas
  • Las imágenes están en data.sprites.front_default.
  • Los tipos en data.types[].type.name.
  • Cache: un simple const cache = {}; a nivel módulo, antes del fetch revisa if (cache[nombre]) return cache[nombre].

✅ Autocomprobación

★

Bonus — Debounce y cancelación

Difícil

Mejora el buscador de Pokémon: que busque mientras escribe el usuario (sin botón), pero con debounce de 300ms para no saturar la API. Bonus extra: usar AbortController para cancelar peticiones obsoletas cuando el usuario sigue escribiendo.

Esto es exactamente lo que hacen los buscadores de Google, Algolia, etc. Si lo logras, ya manejas un patrón de producción.
