🔴 Ejercicio guiado — Consumir PokeAPI

Tienes la UI lista. Tu misión: hacer que esta Pokeball muestre un Pokémon real consumiendo PokeAPI.

🎯 Qué vas a aprender

  • Consumir una API REST pública con fetch y async/await.
  • Manejar los 3 estados clave de cualquier petición: cargando, éxito, error.
  • Renderizar datos dinámicos en el DOM (sin frameworks).
  • Implementar un cache simple para no refetchear lo que ya tienes.

👀 Punto de partida visual

La Pokeball animada de abajo ya está construida (CSS puro). Cuando termines tu ejercicio, el sprite del Pokémon, su nombre y sus tipos deberían aparecer dentro de ella.

ℹ️ Esta página tiene una implementación parcial

El input, botón y contenedores ya están en el HTML con sus id. Tu trabajo es escribir el JavaScript que los conecta con PokeAPI. Abajo está la guía completa.

📋 Fases del ejercicio

1 Construir los controles

Agrega al HTML:

  • Un <input> de texto con un placeholder claro (ej. "pikachu, 25, charizard...").
  • Un <button> con texto "Buscar".
  • Un contenedor (ej. <div> o <p>) donde mostrarás mensajes de estado ("Buscando...", "No encontrado", etc.).

Aplícales un estilo decente (no tienen que ser bonitos, sí usables). Asígnales id a los 3 elementos para poder seleccionarlos desde JS.

2 Conectar los eventos

Cuando se hace click en el botón O se presiona Enter en el input, llamar a una función buscarPokemon(nombre) con el valor del input limpio (.trim().toLowerCase()). Antes del fetch, muestra "Buscando..." en el contenedor de estado y oculta el #pokeDisplay.

3 Llamar a PokeAPI

Endpoint: https://pokeapi.co/api/v2/pokemon/<nombre>. Usa fetch con async/await. Recuerda verificar response.ok — si es 404, el Pokémon no existe.

4 Mostrar el resultado

Del JSON recibido, extrae:

  • Nombre: data.name → ponlo en #pokeNombre
  • Imagen: data.sprites.front_default → ponla como src de #pokeSprite
  • Tipos: data.types es un array. Cada elemento tiene .type.name. Genera un <span> por cada tipo y mételos en #pokeTipos.

Muestra el contenedor #pokeDisplay y actualiza el status a "¡Encontrado!".

5 Manejo de errores

3 casos a cubrir:

  • 404 (no existe): "❌ Pokémon no encontrado. Verifica el nombre."
  • Red caída: "🌐 Sin conexión. Revisa tu internet."
  • Input vacío: "⚠️ Escribe algo antes de buscar."

En todos los casos, el contenedor del Pokémon debe ocultarse.

6 Cache (Bonus)

Crea un objeto const cache = {} a nivel del script. Antes de hacer fetch, revisa si ya tienes ese Pokémon en cache. Si sí, úsalo y muestra "Cargado desde cache ⚡". Si no, hace fetch y guarda el resultado en el cache.
