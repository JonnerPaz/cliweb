🛠️ Retos de LocalStorage

Persistir datos en el navegador es fácil... hasta que tocan los detalles: serialización, valores nulos, cuotas, sincronización. Estos retos te llevan de setItem hasta una mini-app completa.

📋 Cómo trabajar estos retos

  • Copia el código base a un archivo nuevo (ej. reto1.html) y ábrelo en el navegador.
  • Abre las DevTools → pestaña Application → Local Storage para ver lo que guardas en tiempo real.
  • Intenta solo primero. Las pistas están en un desplegable — úsalas solo si te atascas.
  • Marca los criterios de la autocomprobación cuando los vayas cumpliendo.
  • Bonus track: después de resolverlo, borra todo el archivo y reescríbelo desde cero sin mirar.
1

Set / get básico y el caso del null

Fácil

Vas a guardar y leer valores simples. El truco: localStorage solo guarda strings. Cualquier otra cosa se convierte. Y leer una clave que nunca existió devuelve null, no undefined.

📥 Código base

<!DOCTYPE html>
<html lang="es">
<head><meta charset="UTF-8"><title>Reto 1</title></head>
<body>
  <input id="nombre" placeholder="Tu nombre">
  <input id="edad" type="number" placeholder="Tu edad">
  <button id="guardar">Guardar</button>
  <button id="leer">Leer</button>
  <button id="borrar">Borrar todo</button>
  <pre id="salida"></pre>
  <script src="reto1.js"></script>
</body>
</html>
// reto1.js — tu punto de partida
document.getElementById("guardar").addEventListener("click", () => {
  // TODO: leer los inputs y guardarlos en localStorage
});

document.getElementById("leer").addEventListener("click", () => {
  // TODO: leer de localStorage y mostrarlo en #salida
});

document.getElementById("borrar").addEventListener("click", () => {
  // TODO: limpiar todo
});

🎯 Misión

  1. Al hacer clic en Guardar, persiste el nombre y la edad con claves "nombre" y "edad".
  2. Al hacer clic en Leer, muestra ambos valores en #salida. Si una clave no existe, muestra "(no guardado)" en su lugar — no muestres null.
  3. Inspecciona el valor de edad guardado: ¿es número o string? Compruébalo con typeof.
  4. Borrar debe vaciar todo el localStorage de esa página.
💡 Pistas
  • localStorage.setItem(clave, valor) convierte todo a string. setItem("edad", 25) guarda "25".
  • localStorage.getItem("noexiste") devuelve null. Usa ?? "(no guardado)" para dar un valor por defecto.
  • Para borrar todo: localStorage.clear().

Serializar objetos (y sobrevivir al JSON corrupto)

Fácil/Medio

Como localStorage solo guarda strings, los objetos pasan por JSON.stringify al entrar y JSON.parse al salir. ¿Y si alguien manipuló la clave manualmente y quedó malformada? JSON.parse lanza un error y rompe tu app.

📥 Código base

// Helper que vas a construir
function getJSON(key, defaultValue) {
  // TODO: lee, parsea, y si falla devuelve defaultValue
}

function setJSON(key, value) {
  // TODO: serializa y guarda
}

// Prueba
setJSON("usuario", { nombre: "Ana", edad: 25, hobbies: ["pintar", "leer"] });
console.log(getJSON("usuario", null));

// Simula corrupción: en DevTools → Application → Local Storage,
// edita el valor a algo como  {nombre: Ana}  (sin comillas, JSON inválido)
// y vuelve a llamar getJSON. NO debería romperse.
console.log(getJSON("usuario", { nombre: "Anónimo" }));

🎯 Misión

  1. Implementa setJSON(key, value) que serialice con JSON.stringify y guarde.
  2. Implementa getJSON(key, defaultValue) que:
    • Si la clave no existe → devuelve defaultValue.
    • Si existe pero JSON.parse falla → devuelve defaultValue (no rompas la app).
    • Si todo va bien → devuelve el objeto parseado.
  3. Prueba a corromper el valor en DevTools y verifica que tu helper aguanta.
💡 Pistas
  • Envuelve JSON.parse en try/catch.
  • El default debe devolverse tanto cuando getItem devuelve null como cuando el parse falla.
  • Considera devolver una copia del default si es un objeto, para evitar que mutaciones lo contaminen.

3

Theme switcher que sobrevive a recargas

Medio

Construye un selector de tema claro/oscuro: un botón alterna el modo y la elección persiste tras recargar. El truco está en restaurar el tema antes de que el usuario vea el flashazo blanco.

📥 Código base

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Reto 3 — Theme</title>
  <style>
    body { font-family: sans-serif; padding: 2rem; transition: background 0.2s, color 0.2s; }
    body.dark { background: #1a1a1a; color: #f0f0f0; }
    button { padding: 0.6rem 1.2rem; cursor: pointer; }
  </style>
</head>
<body>
  <h1>Demo de tema</h1>
  <p>Cambia el tema y recarga: debe quedarse como lo dejaste.</p>
  <button id="toggle">Alternar tema</button>
  <script src="reto3.js"></script>
</body>
</html>
// reto3.js
// TODO 1: al cargar, lee el tema guardado y aplícalo al body
// TODO 2: el botón #toggle alterna la clase .dark del body
// TODO 3: cada vez que se alterne, guarda el nuevo estado en localStorage

🎯 Misión

  1. Guarda en la clave "theme" el valor "dark" o "light".
  2. Al cargar la página, si el valor guardado es "dark", agrega la clase .dark al <body>.
  3. El botón debe alternar la clase Y actualizar el localStorage en el mismo gesto.
  4. Si nunca se guardó nada, el default es claro.
💡 Pistas
  • body.classList.toggle("dark") devuelve true si la clase quedó añadida, false si quedó quitada — perfecto para decidir qué guardar.
  • Para evitar el flash, ejecuta la lectura del tema antes de pintar contenido pesado (script al final del head o al inicio del body).

Contador con historial de clics

Medio

Un botón +1 que no solo guarda el total, sino también cuándo se hizo cada clic. Muestra los últimos 5 timestamps. Aquí practicas guardar un array como objeto serializado y mantenerlo acotado.

📥 Código base

<!DOCTYPE html>
<html lang="es">
<head><meta charset="UTF-8"><title>Reto 4 — Contador</title></head>
<body>
  <h1>Total: <span id="total">0</span></h1>
  <button id="sumar">+1</button>
  <button id="reset">Reset</button>
  <h2>Últimos 5 clics</h2>
  <ul id="historial"></ul>
  <script src="reto4.js"></script>
</body>
</html>

const $historial = document.getElementById("historial");

function cargar() {
  // TODO: leer historial de localStorage (array de timestamps)
  //       pintar el total y los últimos 5 timestamps
}

document.getElementById("sumar").addEventListener("click", () => {
  // TODO: agregar Date.now() al historial, guardar, re-pintar
});

document.getElementById("reset").addEventListener("click", () => {
  // TODO: limpiar el historial
});

cargar();

🎯 Misión

  1. Guarda un array de timestamps en la clave "clicks".
  2. El total es array.length — no lo guardes por separado.
  3. Muestra los últimos 5 formateados como hora legible (new Date(ts).toLocaleString()).
  4. El historial completo crece sin límite — está bien para este reto, pero piensa: ¿qué pasaría tras un millón de clics?
  5. Reset borra todo y vuelve a 0.
💡 Pistas
  • Reutiliza los helpers getJSON / setJSON del reto 2.
  • array.slice(-5).reverse() te da los últimos 5 en orden cronológico inverso (más reciente arriba).
  • Reset = localStorage.removeItem("clicks") y volver a llamar cargar().

Mini-app: lista de tareas persistente

Difícil

Hora de juntar todo: una to-do list real con creación, marcado como completada, eliminación y persistencia. Bonus: exportar el estado como archivo JSON y manejar el caso de QuotaExceededError.

📥 Código base

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Reto 5 — To-Do</title>
  <style>
    body { font-family: sans-serif; max-width: 500px; margin: 2rem auto; }
    .done { text-decoration: line-through; opacity: 0.6; }
    li { display: flex; gap: 0.5rem; align-items: center; padding: 0.4rem 0; }
    .error { color: crimson; }
  </style>
</head>
<body>
  <h1>📋 Mis tareas</h1>
  <form id="form">
    <input id="nueva" placeholder="Nueva tarea..." required>
    <button>Agregar</button>
  </form>
  <ul id="lista"></ul>
  <button id="exportar">📥 Exportar JSON</button>
  <p id="error" class="error"></p>
  <script src="reto5.js"></script>
</body>
</html>

🎯 Misión

  1. Cada tarea tiene id (puedes usar Date.now() o crypto.randomUUID()), texto, hecha (boolean) y creadaEn.
  2. Render: cada <li> tiene un checkbox (toggle hecha), el texto y un botón de eliminar.
  3. Tareas completadas se muestran con la clase .done.
  4. Todo cambio (agregar, marcar, eliminar) persiste en localStorage.
  5. Envuelve setItem en try/catch: si el navegador lanza QuotaExceededError, muestra un mensaje en #error en vez de romper la app.
  6. Bonus exportar: al clic, genera un Blob con JSON.stringify(tareas, null, 2), crea una URL con URL.createObjectURL y dispara la descarga con un <a download="tareas.json"> sintético.
💡 Pistas
  • Delegación de eventos: pon un solo listener en #lista y usa e.target.dataset.id + e.target.dataset.action para saber qué se clicó.
  • Quota: el límite típico es ~5MB por origen. Para forzar el error en pruebas, guarda "x".repeat(10_000_000) en una clave.
  • Descarga: const url = URL.createObjectURL(blob); const a = document.createElement("a"); a.href = url; a.download = "tareas.json"; a.click(); URL.revokeObjectURL(url);
  • Re-pintar tras cada acción es más simple que actualizar el DOM nodo a nodo. Es rápido suficiente para listas pequeñas.
