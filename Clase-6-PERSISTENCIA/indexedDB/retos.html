🛠️ Retos de IndexedDB

La API es verbosa, pero el concepto es claro: una base de datos real dentro del navegador. Aquí vas a abrirla, escribir, indexar, migrar y construir una mini-app que persiste.

📋 Cómo trabajar estos retos

  • Copia el código base a un archivo HTML nuevo (ej. reto1.html) y ábrelo en el navegador.
  • Abre las DevTools → pestaña Application → IndexedDB. Ahí vas a ver lo que estás creando en vivo.
  • Envuelve los request en promesas. La API nativa con onsuccess/onerror es un dolor — un helper promisify te salva la vida.
  • Usa las pistas solo si te atascas. Están en un desplegable a propósito.
  • Bonus track: después de resolver el reto 5, bórralo todo y reescríbelo desde cero sin mirar. Ahí es cuando realmente lo aprendes.
1

Abrir la DB y crear un object store

Fácil

El punto de partida de IndexedDB es versionar. Cada vez que abres una DB pones un número de versión; si subes ese número, se dispara onupgradeneeded, que es el único lugar donde puedes crear/borrar object stores e índices.

📥 Código base

// reto1.html — solo abre la DB
const request = indexedDB.open("miDB", 1);

request.onupgradeneeded = (event) => {
  const db = event.target.result;
  // TODO: crear object store "usuarios" con keyPath "id"
};

request.onsuccess = (event) => {
  const db = event.target.result;
  console.log("✅ DB abierta:", db.name, "v" + db.version);
};

request.onerror = () => console.error("❌ No se pudo abrir");

🎯 Misión

  1. Dentro de onupgradeneeded, crea un object store llamado "usuarios" con keyPath: "id".
  2. Asegúrate de verificar primero que no exista: if (!db.objectStoreNames.contains("usuarios")).
  3. Abre el archivo en el navegador y mira en DevTools → Application → IndexedDB. Debes ver miDB con el store vacío.
  4. Si ya tenías una miDB de pruebas anteriores, bórrala desde DevTools antes de probar.
💡 Pistas
  • db.createObjectStore(nombre, opciones). Las opciones aceptan keyPath (clave fija) o autoIncrement: true.
  • onupgradeneeded siempre se dispara cuando la DB no existe o cuando subes la versión.
  • Si cambias el esquema, sube la versión: indexedDB.open("miDB", 2).

CRUD básico con promesas

Fácil / Medio

La API de IndexedDB es callback-hell por defecto. Vas a envolver cada operación en una promesa para usar async/await y que el código sea legible.

📥 Código base — helper promisify + esqueleto

// Convierte un IDBRequest en Promise
function promisify(request) {
  return new Promise((resolve, reject) => {
    request.onsuccess = () => resolve(request.result);
    request.onerror   = () => reject(request.error);
  });
}

function abrirDB() {
  return new Promise((resolve, reject) => {
    const req = indexedDB.open("miDB", 1);
    req.onupgradeneeded = (e) => {
      const db = e.target.result;
      if (!db.objectStoreNames.contains("usuarios")) {
        db.createObjectStore("usuarios", { keyPath: "id" });
      }
    };
    req.onsuccess = () => resolve(req.result);
    req.onerror   = () => reject(req.error);
  });
}

async function agregar(usuario) {
  // TODO
}
async function obtener(id) {
  // TODO
}
async function actualizar(usuario) {
  // TODO
}
async function eliminar(id) {
  // TODO
}

// Prueba:
(async () => {
  await agregar({ id: 1, nombre: "Ana", edad: 22 });
  console.log(await obtener(1));
  await actualizar({ id: 1, nombre: "Ana", edad: 23 });
  await eliminar(1);
})();

🎯 Misión

  1. Implementa las 4 funciones usando promisify.
  2. Cada una debe: abrir la DB, abrir una transacción "readwrite" (o "readonly" en obtener), llamar al método del store (add, get, put, delete) y devolver la promesa.
  3. Recuerda: add falla si la clave ya existe; put inserta o reemplaza.
  4. Verifica en DevTools que los datos aparecen, cambian y desaparecen.
💡 Pistas
  • Patrón repetido: const tx = db.transaction("usuarios", "readwrite"); const store = tx.objectStore("usuarios"); return promisify(store.add(usuario));
  • actualizar usa store.put(usuario).
  • Si necesitas el resultado de la transacción completa (no solo el request), también puedes envolver tx.oncomplete.

Listar todos y filtrar — getAll vs cursor + índice

Medio

Hay dos formas de leer muchos registros: traer todo y filtrar en JS, o crear un índice y usar un cursor con rango. La primera es cómoda; la segunda escala.

📥 Código base

function promisify(request) {
  return new Promise((res, rej) => {
    request.onsuccess = () => res(request.result);
    request.onerror   = () => rej(request.error);
  });
}

function abrirDB() {
  return new Promise((resolve, reject) => {
    const req = indexedDB.open("miDB", 1);
    req.onupgradeneeded = (e) => {
      const db = e.target.result;
      const store = db.objectStoreNames.contains("usuarios")
        ? null
        : db.createObjectStore("usuarios", { keyPath: "id" });
      // TODO: crear índice "porEdad" sobre la propiedad "edad"
    };
    req.onsuccess = () => resolve(req.result);
    req.onerror   = () => reject(req.error);
  });
}

// A) Filtro en JS con getAll
async function mayoresDeFacil(edadMin) {
  const db = await abrirDB();
  const store = db.transaction("usuarios", "readonly").objectStore("usuarios");
  const todos = await promisify(store.getAll());
  return todos.filter(u => u.edad >= edadMin);
}

async function mayoresDeIndice(edadMin) {
  // ...
}

🎯 Misión

  1. Inserta unos 5-10 usuarios con edades variadas usando el CRUD del reto 2.
  2. Agrega un índice "porEdad" en onupgradeneeded: store.createIndex("porEdad", "edad"). Sube la versión a 2 para que se dispare la actualización.
  3. Implementa mayoresDeIndice usando store.index("porEdad").openCursor(IDBKeyRange.lowerBound(edadMin)) y acumulando con cursor.continue().
  4. Verifica que ambas funciones devuelvan lo mismo. Compara: ¿cuál te parece más legible? ¿Cuál ahorraría memoria si tuvieras 10 millones de filas?
💡 Pistas
  • IDBKeyRange.lowerBound(18) = "edad ≥ 18". También existen upperBound, bound(a, b) y only(x).
  • Cursor: dentro de request.onsuccess, si cursor no es null, haces cursor.value y cursor.continue(); cuando es null, terminaste.
  • Para promisificar el cursor: resuelve la promesa cuando cursor === null, acumulando en un array externo.

Migración de esquema sin perder datos

Medio

Esto es lo que hace a IndexedDB distinto de localStorage: puedes evolucionar el esquema. Vas a llevar tu DB de la versión 1 a la versión 2 agregando algo nuevo, sin borrar lo que ya está dentro.

📥 Código base

function abrirDB() {
  return new Promise((resolve, reject) => {
    const req = indexedDB.open("miDB", 2); // ← versión 2

    req.onupgradeneeded = (event) => {
      const db = event.target.result;
      const oldVersion = event.oldVersion;
      const tx = event.target.transaction; // transacción de upgrade

      if (oldVersion < 1) {
        db.createObjectStore("usuarios", { keyPath: "id" });
      }

      if (oldVersion < 2) {
        // TODO: agregar índice "porNombre" SIN borrar datos existentes
        // TODO (opcional): crear un nuevo store "preferencias" con keyPath "userId"
      }
    };

    req.onsuccess = () => resolve(req.result);
    req.onerror   = () => reject(req.error);
  });
}

🎯 Misión

  1. Antes de empezar, inserta 3-4 usuarios en la versión 1 (cárgalos manualmente o desde el reto 2).
  2. Sube la versión a 2 y, dentro del bloque if (oldVersion < 2), obtén el store con tx.objectStore("usuarios") y crea el índice "porNombre" sobre la propiedad nombre.
  3. Crea un segundo store opcional "preferencias" con keyPath: "userId".
  4. Refresca. Verifica que los usuarios siguen ahí y que ahora existe el índice nuevo.
💡 Pistas
  • Durante onupgradeneeded, event.target.transaction ya está activa: no abras una nueva. Úsala para acceder al store existente.
  • El patrón if (oldVersion < N) en cascada es como las migraciones de cualquier ORM: garantiza que un usuario que viene de v0 ejecute v1 + v2.
  • Si rompes algo en DevTools, "Delete database" y empieza de nuevo.

5

Mini-app: catálogo de libros con búsqueda

Difícil

Aquí juntas todo: persistencia real, CRUD completo, índice para búsqueda y una transacción masiva. Un usuario debería poder cerrar la pestaña, abrirla mañana, y todos sus libros siguen ahí.

📥 UI mínima

<input id="titulo">
<input id="autor">
<input id="anio" type="number">
<button id="btnAgregar">Agregar libro</button>

<input id="busqueda" placeholder="Buscar por título...">
<ul id="lista"></ul>

<button id="btnSeed">Cargar 50 libros de ejemplo</button>

🎯 Misión

  1. DB: "libreria" v1. Store: "libros" con keyPath: "id" + autoIncrement: true. Índice: "porTitulo" sobre "titulo".
  2. Helper promisify obligatorio. Todas las funciones async.
  3. CRUD completo accionado desde la UI: agregar, eliminar (botón por fila), listar.
  4. Búsqueda: al teclear en #busqueda, filtra usando el índice porTitulo con IDBKeyRange.bound(prefijo, prefijo + "￿").
  5. Persistencia real: cierra la pestaña, ábrela de nuevo, los libros siguen.
  6. Bonus: botón "Cargar 50 libros" que inserta un array de 50 con una sola transacción (no 50). Mide en consola cuánto tarda.
💡 Pistas
  • Una transacción puede ejecutar muchos store.add(...) seguidos. Lo que tarda es commitearla, no cada add. Por eso 50 adds en 1 transacción es muchísimo más rápido que 50 transacciones.
  • Para búsqueda prefijo: el truco IDBKeyRange.bound("ja", "ja￿") trae todo lo que empieza con "ja" (porque ￿ es el último char Unicode).
  • Debounce el input de búsqueda (ej. setTimeout/clearTimeout) para no atacar la DB en cada tecla.
  • El botón de eliminar de cada fila: usa data-id y un único listener delegado en el <ul>.
