🛠️ Retos de HTML

No basta con leer: copia, rompe, rehaz y entiende. Cada reto te da un punto de partida — tu trabajo es transformarlo.

📋 Cómo trabajar estos retos

  • Copia el código base a un archivo nuevo (ej. reto1.html) y ábrelo en el navegador.
  • Lee la misión antes de tocar nada. Asegúrate de entender qué pide.
  • Intenta solo primero. Las pistas están en un desplegable — úsalas solo si te atascas.
  • Marca los criterios de la autocomprobación cuando los vayas cumpliendo.
  • Bonus track: después de resolverlo, borra todo el archivo y reescríbelo desde cero sin mirar. Ahí es cuando realmente lo aprendes.
1

De HTML inválido a HTML correcto

Fácil

Te entregan un archivo HTML que funciona a medias. El navegador es indulgente y muestra algo, pero hay errores: etiquetas mal cerradas, falta estructura básica, idioma incorrecto.

📥 Código base — cópialo tal cual

<html>
  <title>Mi primera página
  <body>
    <h1>Bienvenido</h2>
    <p>Esta es una página web.
    <p><b><i>Texto en negrita y cursiva</b></i>
  </body>

🎯 Misión

  1. Agrega el <!DOCTYPE html>.
  2. Declara el idioma de la página como español.
  3. Crea el <head> y mete dentro el <title> y un <meta charset>.
  4. Cierra correctamente todas las etiquetas.
  5. Corrige el anidamiento de <b> y <i>.
💡 Pistas (úsalas solo si te atascas)
  • El atributo de idioma va en <html lang="...">.
  • Una etiqueta abierta como <b><i>...</b></i> rompe la regla: la última que se abre, primera que se cierra.
  • El <p> también necesita cierre, aunque el navegador "perdone".

2

De <div> soup a HTML semántico

Medio

Este código se ve bien, pero un lector de pantalla o Google no entienden qué es qué: todo son <div>. Tu misión es traducirlo a HTML semántico sin cambiar lo que el usuario ve.

📥 Código base

<div class="top">
  <div class="logo">MiBlog</div>
  <div class="menu">
    <div><a href="#">Inicio</a></div>
    <div><a href="#">Posts</a></div>
  </div>
</div>

<div class="post">
  <div class="title">¿Por qué semántica?</div>
  <div class="meta">Publicado el 12 de mayo</div>
  <div class="body">
    <div>HTML semántico ayuda a accesibilidad y SEO.</div>
    <div>Imagen relacionada:</div>
    <div><img src="x.jpg"></div>
  </div>
</div>

<div class="bottom">© 2026 MiBlog</div>

🎯 Misión

  1. Reemplaza cada <div> por la etiqueta semántica correcta (header, nav, main, article, section, figure, footer...).
  2. El menú debe ser una lista (<ul>/<li>) dentro de <nav>.
  3. El título del post debe ser un <h1> o <h2> según corresponda en la jerarquía.
  4. La fecha de publicación usa <time datetime="2026-05-12">.
  5. La imagen sin texto alternativo es un fallo de accesibilidad: agrega un alt descriptivo.
💡 Pistas
  • "top" suele ser <header>, "bottom" suele ser <footer>.
  • "post" individual = <article>. Una imagen con contenido relacionado = <figure>.
  • La jerarquía de títulos importa: si h1 es el sitio, el post puede empezar en h2.

3

Recrea esta tarjeta desde cero

Medio

Aquí hay una "tarjeta de perfil" descrita en palabras. No te damos el HTML. Tu trabajo es construirla desde un archivo vacío usando solo las etiquetas correctas. (Sin CSS por ahora — el foco es la estructura.)

📐 Especificación de la tarjeta

  • Una imagen de avatar (puede ser cualquier URL de placeholder, ej. https://i.pravatar.cc/150) con texto alternativo.
  • El nombre de la persona como título principal de la tarjeta.
  • El cargo debajo del nombre, en texto destacado pero secundario.
  • Una biografía corta de 2 párrafos.
  • Una lista no ordenada de habilidades (al menos 3).
  • Un enlace al portafolio que abra en una pestaña nueva.
  • Un correo de contacto que, al hacer clic, abra el cliente de correo.
💡 Pistas
  • Toda la tarjeta debería estar envuelta en un <article> o <section>.
  • Para abrir en pestaña nueva: target="_blank" (y por seguridad rel="noopener").
  • Para enlaces de correo: href="mailto:tu@email.com".
  • El cargo puede ir en un párrafo con clase, o en una etiqueta como <p>/<small>.

4

Tabla de horarios accesible

Medio

Recibes los datos de un horario semanal. Tu reto: convertirlos en una tabla HTML correcta y accesible (no en una serie de divs).

📥 Datos a representar

Columnas: Hora, Lunes, Martes, Miércoles, Jueves, Viernes

08:00 — Matemáticas, --, Matemáticas, --, Inglés
10:00 — Física, Historia, Física, Historia, Lab
12:00 — --, Programación, --, Programación, --

🎯 Misión

  1. Construye una <table> con <thead> y <tbody>.
  2. Los encabezados de columna usan <th scope="col">.
  3. La columna "Hora" de cada fila usa <th scope="row">.
  4. Agrega un <caption> que describa la tabla.
  5. Cuando no haya clase, deja la celda vacía (no escribas "--").
💡 Pistas
  • scope ayuda a lectores de pantalla a saber si un th describe una fila o columna.
  • <caption> va inmediatamente después de <table>.

5

Formulario de inscripción usable

Difícil

Un formulario mal hecho frustra al usuario. En este reto vas a construir uno donde cada control tenga su etiqueta asociada, validación nativa del navegador y orden lógico.

📥 Campos requeridos

  • Nombre completo — texto, obligatorio, mínimo 3 caracteres.
  • Email — tipo email, obligatorio.
  • Fecha de nacimiento — tipo date, obligatorio.
  • Edad — número entre 16 y 99.
  • Curso de interés — selector con opciones: HTML, CSS, JavaScript.
  • Nivel — radio buttons: Principiante, Intermedio, Avanzado.
  • Intereses — checkboxes múltiples: Frontend, Backend, Diseño, Mobile.
  • Comentarios — área de texto, opcional, máximo 500 caracteres.
  • Aceptar términos — checkbox obligatorio.
  • Botón de Enviar y botón de Limpiar.

🎯 Reglas no negociables

  1. Cada <input> debe estar asociado a un <label> mediante for/id.
  2. Los radios y checkboxes relacionados van agrupados en un <fieldset> con <legend>.
  3. Usa los atributos correctos: required, min, max, minlength, maxlength, type.
  4. Usa placeholder solo donde aclare formato (ej. email), nunca como sustituto de la etiqueta.
  5. El formulario debe poder enviarse y mostrar errores nativos del navegador si algo falla.
💡 Pistas
  • El name es lo que se envía al servidor; el id es lo que conecta con label for. Ambos suelen coincidir, pero son cosas distintas.
  • Para limitar texto de un input: minlength / maxlength. Para números: min / max.
  • Botón limpiar: <button type="reset">.
