🎨 Retos de CSS

Aplicar reglas no es entender CSS. Copia, rompe, observa qué cambia y reconstrúyelo.

📋 Cómo trabajar estos retos

  • Copia el HTML base en un archivo (ej. reto1.html) y escribe el CSS dentro de un <style> en el <head>.
  • No copies la solución de ningún lado — pierde el reto.
  • Si la página no se ve como esperabas, abre el inspector (clic derecho → Inspeccionar) y revisa qué reglas aplican.
  • Bonus track: después de resolver, escribe tu solución en un papel sin mirar la pantalla. Si puedes, lo entendiste.
1

El selector correcto

Fácil

Tienes este HTML. Debes pintar cada texto del color correcto usando un único selector por regla y sin tocar el HTML.

📥 HTML base

<h1>Título principal</h1>
<p>Párrafo normal.</p>
<p class="destacado">Este es importante.</p>
<p id="alerta">¡Atención!</p>
<a href="#">Un enlace</a>
<ul>
  <li>Item A</li>
  <li class="destacado">Item B</li>
</ul>

🎯 Misión

  1. El h1 debe ser azul.
  2. Todos los párrafos deben tener fondo gris claro.
  3. Todo elemento con clase .destacado (sea párrafo o li) debe ir en negrita.
  4. El elemento con id #alerta debe ser texto rojo.
  5. Solo los links dentro de listas deben tener subrayado punteado.
  6. Los li que estén dentro de un ul deben tener un margen izquierdo de 20px.
💡 Pistas
  • Selector por etiqueta: p { }
  • Selector por clase: .destacado { }
  • Selector por id: #alerta { }
  • Selector descendiente: ul a { } (a dentro de ul)
  • Subrayado punteado: text-decoration: underline dotted;

2

Guerra de especificidad

Medio

Tu compañero te pasa este código. Dice "no me cambia el color del párrafo, no sé por qué". Sin modificar el HTML, haz que el texto se vea verde.

📥 Código que recibes

<style>
  p { color: black; }
  .texto { color: blue; }
  #intro { color: red; }
  div p { color: purple; }
</style>

<div>
  <p id="intro" class="texto">Tengo que verme verde.</p>
</div>

🎯 Misión

  1. Antes de tocar nada: predice de qué color se ve actualmente el párrafo y por qué.
  2. Agrega una sola regla CSS que lo haga verde. Sin !important en el primer intento.
  3. Después, intenta hacerlo verde con !important y entiende por qué funciona aunque sea "trampa".
  4. Calcula y anota la especificidad de cada selector existente en formato (a,b,c,d) — donde a=style inline, b=ids, c=clases/atributos/pseudoclases, d=etiquetas.
💡 Pistas
  • Especificidad: #intro = (0,1,0,0), div p = (0,0,0,2), .texto = (0,0,1,0).
  • Gana el que tenga mayor especificidad. Empate ⇒ gana el último escrito.
  • Para superar un #id necesitas otro id (o más), o una combinación que sume.

Box model: ¿cuánto mide en realidad?

Medio

Tienes este código. Antes de abrirlo, calcula a mano cuánto ocupa la caja en pantalla (alto y ancho). Después ábrelo, abre el inspector y verifica.

📥 Código base

<style>
  .caja {
    width: 200px;
    height: 100px;
    padding: 20px;
    border: 5px solid red;
    margin: 10px;
  }
</style>

<div class="caja">Hola</div>

🎯 Misión

  1. Calcula a mano cuánto ocupa la caja con el modelo content-box (el default).
  2. Ahora añade box-sizing: border-box; a la regla. Vuelve a calcular.
  3. Abre el inspector → pestaña "Computed" → verifica que tu cálculo coincida.
  4. Modifica el padding a 50px sin cambiar el tamaño total visible. (Con border-box podrás.)
  5. Explica en una línea por qué * { box-sizing: border-box; } es el primer "reset" que se aplica en casi todos los proyectos reales.
💡 Pistas
  • content-box: width = solo contenido. El padding y border SUMAN al tamaño total.
  • border-box: width = contenido + padding + border. El total es exactamente lo que pediste.
  • El margin nunca cuenta como "tamaño de la caja", es espacio externo.

4

block vs inline vs inline-block

Medio

Copia este HTML. Tu reto: lograr 3 layouts distintos del MISMO HTML solo cambiando la propiedad display.

📥 HTML base (no lo modifiques)

<style>
  .item {
    background: #5cb6ff;
    padding: 12px;
    margin: 4px;
    width: 100px;
    height: 60px;
  }
</style>

<span class="item">A</span>
<span class="item">B</span>
<span class="item">C</span>

🎯 Misión — produce 3 versiones

  1. Versión inline (default de span): observa que width y height NO funcionan. Anota por qué.
  2. Versión block: agrega display: block; a .item. ¿Qué pasa con el ancho? ¿Y con cómo se apilan?
  3. Versión inline-block: cámbialo a display: inline-block;. Compara con las dos anteriores.
  4. Reto extra: en la versión inline-block, ¿de dónde sale ese pequeño espacio blanco entre cajas que NO pediste? Investiga y resuélvelo.
💡 Pistas
  • inline ignora width/height porque su tamaño lo determina su contenido.
  • block ocupa todo el ancho disponible y fuerza salto de línea.
  • El "espacio fantasma" en inline-block viene del espacio en blanco del HTML entre etiquetas. Hay varias formas de eliminarlo — busca al menos una.

5

Recrea un botón profesional desde cero

Difícil

Te describimos un botón en palabras. Tu trabajo: implementarlo desde un archivo vacío, sin librerías.

📐 Especificación del botón

  • Texto: "Continuar →" centrado.
  • Fondo azul (#2965f1), texto blanco, sin borde visible.
  • Padding interno generoso: 12px arriba/abajo, 28px izquierda/derecha.
  • Esquinas redondeadas (8px).
  • Letra ligeramente más gruesa de lo normal y sin mayúsculas forzadas.
  • Al pasar el mouse: se oscurece ligeramente y la flecha se mueve 4px a la derecha.
  • Al hacer click (mientras está presionado): se ve "hundido" (1px más abajo, fondo más oscuro).
  • Cuando tiene foco por teclado (tab): un outline visible de 3px en color claro, NO la línea punteada fea del default.
  • La transición de estado debe ser suave (no abrupta), 150ms.
💡 Pistas
  • Para mover la flecha solo en hover: pon la flecha en un <span> dentro del botón con display: inline-block y anímalo con transform: translateX(...).
  • Para el efecto "hundido": :active { transform: translateY(1px); }.
  • Nunca uses outline: none; sin reemplazarlo — rompes accesibilidad para usuarios de teclado.
  • Para transiciones suaves: transition: all 0.15s ease;.

Bonus — Variables CSS

Difícil

Toma tu solución del reto 5 y refactorízala usando variables CSS (--color-primary, --radius, --gap, etc.) declaradas en :root. Luego crea una segunda versión "modo oscuro" cambiando solo las variables, no las reglas.

Esta es exactamente la técnica que usamos en este propio sitio (assets/base.css) para que cada clase tenga su paleta. Si lo logras, ya estás aplicando un patrón profesional real.
